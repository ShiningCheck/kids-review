# 音频降噪

手机录口播通常有稳定底噪（环境声、风、设备底噪）。用 ffmpeg 自带的 `afftdn` 就能压掉不少。

## 快速用

```bash
python render.py ... --denoise mid --loudnorm
```

`--denoise` 可选 `off / light / mid / strong`，也可以直接传 ffmpeg 滤镜串。
`--loudnorm` 加在最后做整体响度归一（-16 LUFS），降噪后建议开。

## 预设

| 预设 | 滤镜 | 信噪比提升 |
|---|---|---|
| `light` | `highpass=f=80,afftdn=nf=-30:nr=16` | +3.3 dB |
| `mid` | `highpass=f=80,afftdn=nf=-25:nr=24` | +6.6 dB |
| `strong` | `highpass=f=80,afftdn=nf=-22:nr=32` | +9.2 dB |

实测素材：手机户外录音，噪底约 −35 dB，语音约 −18 dB（信噪比 17.3 dB）。
三档处理后语音电平只掉 0~0.3 dB —— **只压噪，不动人声**。

## ★ 最大的坑：`nf` 的参数轴是反的

`afftdn` 的 `nf` 是「噪声门限」，不是「降噪强度」。**值越不负，反而越激进**：

```
nf=-45  → 只压 -45dB 以下的，几乎没效果
nf=-25  → 压 -25dB 以下的，明显
nf=-22  → 最强
```

我最初按「越大越强」的直觉写成了 `nf=-25 / -35 / -45` 的三档，
结果「强档」反而最弱，而且**三档输出几乎一样**，白折腾一轮。

`nr`（noise reduction，默认 12）只微调削减量，**真正决定效果的是 nf**。

## 另一个坑：`tn=1` 自动跟踪噪声基本没用

`afftdn=tn=1:nr=X` 看着最"智能"，实测在几分钟的片段上收敛不好，
输出和原始**逐样点一致**（噪底 -35.2 → -35.2，一点没降）。别用。

要自动估计就用 `asendcmd`/`anlmdn`，或者干脆手工定 nf。

## 怎么验证降噪真的生效（必做）

不要靠耳朵，用**真实静音间隙**当标尺：

```bash
# 1) 找片段里最安静的位置（说话间隙）
for i in $(seq 0 32); do
  ffmpeg -ss $(echo "$i*0.4"|bc) -t 0.4 -i seg.wav -af volumedetect -f null - 2>&1 | grep mean_volume
done
# 取数值最大的那个窗口（dB 值最高 = 最安静）

# 2) 对比各档在这个窗口的电平（噪底）和说话窗口的电平（人声）
```

判读标准：
- **噪底明显下降 + 人声电平基本不变** = 有效
- 两者一起下降 = 降过头了，人声也被削

## 试听对比的做法（给用户选档位）

做一条对比音轨：`TTS 报段落名 → 原声 → TTS → 轻 → TTS → 中 → TTS → 强`，
每段用同一个素材片段。TTS 用 `edge-tts`（已装）。

**不要加 `loudnorm`**：它是动态处理，会压缩各段之间的差异，A/B 判断就不准了。
只做拼接就行（各档电平本来就接近）。

```python
# 三段拼接要点：所有输入先 aresample=48000 + aformat 统一，
# 每段后面 apad=pad_dur=0.45 留间隔，再 concat=n=N:v=0:a=1
```

## 不是每段素材都需要降噪

先测噪底再决定。噪底低于 −45 dB 的素材（安静室内）降噪收益很小，
强行降噪反而会引入「水下音」的听感。**先给用户听对比，别默认全开。**
